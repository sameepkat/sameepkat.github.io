No React Is Not Really About Websites

2026-10-27

Most people hear “React” and just think of Websites and User Interfaces. And while, React is used for those purposes, at it’s core, react is just a diffing engine. All it does it look at the first component tree and the second one, then determines what exactly needs to change between them. This is called Reconciliation. This allows only the changed components to be re-rendered instead of the whole component tree.

So, fundamentally React is not just a website library. It is a:

> Declarative tree reconciliation and synchronization engine, originally designed for user interfaces.

React’s Architecture

React, by itself does not know what <div> really means. These are browser-specific things that are handled by a separate package (react-dom) that you might see being downloaded as a dependency when you try to create a react web app.

Similarly, React Native uses React’s engine to create mobile specific components. Here, React Native acts a bridge for OS-specific components and React is the reconciliation engine for changed components.

You might have heard that Windows uses React for their Start Menu. It is the same principle here as well. They use React Native Windows for rewriting native windows code with React. Renderer

Renderer is the exact term for the entity responsible for creating UI for a specific platform. It translates the reconciliation decisions into operations for a particular target.

You may have already heard of many react renderers out there.

1. React DOM
   Browser DOM Node

2. React Native
   Native Android/ iOS view

3. React Three Fiber
   Three.js Object

and so on.

The React Documentation describes the renderer as calling components to determine what should be displayed on the screen. It is followed by committing the necessary changes to the DOM or Native Views or something else.
